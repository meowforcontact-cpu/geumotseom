## 1. 디자인 정체성 — 이후 작업에서 유지할 취향

- 2000년대 일본 GBA/DS 레트로 게임과 파스텔 캐릭터 문구류. 둥글고 말랑하고 따뜻한 인상, 작은 화면에서도 인식되는 진짜 도트. 귀엽지만 지나치게 유아적이거나 획일적인 캐릭터는 지양.
- 귀여움은 픽셀 수를 늘리는 것이 아니라 **비례·실루엣·얼굴 배치·성격·행동**에서 먼저 만든다. 인간 SD 데포르메의 대두/작은 몸, 귀여운 캐릭터 커서의 여백/작은 눈·입, 햄토리의 몸짓/표정, 포켓몬의 종별 특징을 각기 참고한다.
- 개별 캐릭터 정체성은 색만 바꾸지 않고 얼굴형, 귀, 꼬리, 자세, 대표 특징으로 구분한다. 같은 세계에 속하되 동일 머리·몸 도장을 반복하지 않는다.
- 얼굴은 가로로 넓은 둥근 볼, 넓은 미간과 구체적인 눈 형태, 작은 입, 절제된 볼터치. 슬퍼 보이거나 화난 눈 대신 새침하고 나른한 인상. 작은 눈이지만 감은 눈처럼 가로 한 줄로 만들지 않는다.
- 파스텔 블루/핑크/크림, 부드러운 채도, 단단한 색 덩어리와 절제된 명암. 캐릭터 외곽선은 몸색과 잘 어울리는 회갈색/회보라 등 후보, 가구 공통 짙은 갈색 외곽선 규칙은 유지. 블러, 그라데이션, AA, 의미 없는 노이즈·과도한 그림자 금지. 억지 팔레트 축소는 하지 않는다.
- 기본 몸체는 무의상·무장식, 착용 가능한 의상/모자/리본은 별도 파츠로 고려.

## 3. 신규 첫 고양이 시안 (검토용)

- 아이보리/크림 털의 이족보행 Scottish Fold 모티프. 귀만 검정(차콜/회보라 검정 비교 가능); 머리/몸/꼬리에는 검은 무늬를 추가하지 않는다. 귀는 낮고 앞으로 접혀 보이는 고양이 귀, 강아지처럼 좌우로 길게 늘어뜨리지 않는다.
- 머리 높이:목 아래 몸 높이 약 2:1 목표. 기존 후보 대비 몸통 높이 약 25~30% 감소를 비교한다(수치는 검토용). 넓고 말랑한 볼, 목은 거의 보이지 않으며 아주 짧지만 손과 발이 구별되는 팔·다리. 의상 부착과 먹기/놀이가 가능한 몸체를 유지.
- 얼굴: 눈 사이 여백을 더 넓히고 눈을 작은 면적의 반눈으로 설계. 눈 위쪽이 살짝 덮이되 눈꼬리가 위로 크게 솟지 않음. 작은 코·입과 은은한 핑크 볼, 수염·눈썹·이마 무늬·리본·벨 없음.
- 이전 실험 S48-22의 새침한 인상과 S48-01의 안정된 형태, 접힌 귀 후보의 귀 형태를 각각 관찰한다. 기존 추천 후보를 복제하거나 특정 후보를 승인된 원본으로 간주하지 않는다.
- 비교안: A. 단정한 낮은 폴드 귀+새침한 반눈 / B. 더 둥근 볼+살짝 더 벌어진 눈. 형태 변수 하나씩 비교한 뒤 한 디자인을 선택; 추가 생성 비용은 승인 전 집행하지 않는다.

## 4. 픽셀 구조 및 규격 비교 (REVIEW)

| 캔버스 | 픽셀 수 | 판단 기준 |
| --- | ---: | --- |
| 32×32 | 1,024 | 기존 기준. 굵고 간결한 레트로 도트. 각진 볼·눈의 1px 변화와 손/의상 공간 제약 |
| 48×48 | 2,304 | 표정/볼 곡선/귀 색 분리 여유. 픽셀 정체성·실제 화면의 선명함 유지 여부 |
| 64×64 | 4,096 | 복잡한 캐디·미세한 눈·의상/손 포즈 표현. 불필요한 명암·밀도와 작업량 증가 여부 |

- 32/48 실제 사례를 대조하고 48/64 새 시안은 각각 원본 논리 그리드에서 독립 제작한다. 단순 확대나 1.5배 보간으로 대신하지 않는다. 캔버스의 총 픽셀과 유효 캐릭터 영역(bbox), 화면상 크기, 에셋 파일 용량을 분리해 기록한다.
- 동일 비례·표정·참조 역할·카메라·색감·발점으로 1배 원본 및 정수배(nearest-neighbor) 비교판, 게임 내 실제 동일 표시 크기의 장면을 함께 검수한다. 런타임 정수 배율과 가구 스케일 충돌 시 기록하고 결정 전 코드 수정하지 않는다.
- 48/64가 32보다 각각 2.25/4배의 원본 면적이지만 그것이 생성비·프레임 비용·파일 크기·렌더링 부담이 정확히 같은 비율로 늘어난다는 뜻은 아니다. 의상/8방향/행동 조합에서 전체 제작량과 실제 모바일 가독성을 비교한다.
- 인간 SD 비즈 도안의 43~67급 캔버스는 복잡한 얼굴/머리/의상의 가능성을 보이지만 게임 이동 원본까지 이 해상도로 맞출 필요는 없다. 이동 스프라이트와 대화/도감용 큰 얼굴 초상화(48~64 등 별도 후보)를 분리할 수 있다.
- 가구 색수는 **소재 하나당 기본 2색(최대 3색) + 공통 외곽선 별도**. 캐릭터는 승인 레퍼런스와 실제 픽셀 배치로 판정하며 전체 이미지 임의 색수 제한을 적용하지 않는다.

## 5. 모션·표정·착용

Hamtaro처럼 작은 화면에서도 한 눈에 행동이 보여야 한다. 얼굴만 바꾸는 동작과 전신 움직임을 구분한다. 얼굴과 귀, 손, 몸 기울기, 발, 꼬리의 짧은 변화로 행동을 분명히 하고 중간 프레임에서 눌림·반동을 허용하되 정체성·기준 비례가 무너지지 않게 한다.

- 기본 8방향: 정면/45도 대각선/측면/후면을 같은 시점과 발점으로 제작. 좌우 대칭 복제는 비대칭 디자인과 움직임이 없을 때만.
- 승인 PET 명세의 표정: 기본·행복·졸림(콧방울)·슬픔(눈물)·놀람·사랑·어질어질·부끄러움·삐짐. 화남은 기본으로 대체. 눈·입·볼/효과의 고정 앵커와 재사용 검토.
- 승인 행동: 대기(깜빡임/귀 움직임), 걷기, 먹기, 쓰다듬기 반응, 앉기, 눕기, 잠자기, 놀기. 필요 프레임·방향은 [PET](quality/PET_CARE_SPEC.md)를 따른다. 대화는 표정/텍스트 말풍선 중심. 모든 포즈·표정을 무작정 곱해 대량 생산하지 않는다.
- 대기/걷기에서 발점은 고정; 점프·눕기 등 변화가 필요한 동작은 기준 발점/접지 위치를 별도 명시. 손에 든 물건과 몸, 가구 사용점 및 깊이 정렬을 일치시킨다.
- 옷/모자/장신구 파츠는 기본 원본에 영구 합성하지 않는다. 방향/프레임의 머리·목·몸통·손 앵커 및 전후 레이어가 일정해야 한다. 의상 시안은 대표 동작과 겹침 여부를 함께 검수한다.
- 포즈와 표정이 커져도 렌더러의 고정 좌표를 먼저 바꾸지 않는다. 승인 원본을 기준으로 대기→8방향→걷기→돌보기→착용 순으로 단계 검토.

## 6. 공간·가구·월드

- 현행 4:3 미들앵글 2.5D와 170×128 좌표는 보호. 리뉴얼 시안 목표: 가로 4:3(예: 1024×768 표시), 3/4 탑다운 평행투영으로 다마고치보다 내려다보는 느낌. 24×18 타일 중 상단 4행 벽, 하단 14행 바닥의 별도 후보; 논리 픽셀/표시 픽셀과 혼동 금지.
- 뒷벽·큰 창문(흰 커튼)·아이보리 몰딩·화이트우드와 밝은 나무 바닥, 앞벽 없음, 최소한의 좌우 경계. 사다리꼴 투시/소실점/아이소메트릭 혼용 금지. 넓은 중앙 바닥·이동 통로 확보.
- 벽/바닥/창문 건축 요소만 배경에 고정하고 조명·식물·러그·가구 등은 독립 PNG로 분리한다. 실제 방의 크기와 앵커·바닥/벽/상판 배치 가능 여부, 깊이·통과 경계를 기록.
- 월드맵 후보: 둥근 섬과 바다, 중앙 광장, 주변 주택/상점/공원, 하단 선착장, DS RPG 느낌의 길 연결. 공간 발견·수집·배치의 재미 중심. 기존 맵·출입구 확정 변경 없음.

## 7. 메뉴·도감·HUD

- 사용자가 선호한 파스텔 블루 레트로 링바인더 다이어리와 스크랩북, 펼쳐진 페이지의 비대칭 각도·겹친 종이·블루 링 4개·우측 인덱스를 시각 기준으로 참고. 왼쪽 3 : 오른쪽 7 후보. 격자 배경, 색과 여백으로 섹션 구조가 드러나게.
- 왼쪽에는 프로필/닉네임, 보유 냐냐냥, XP, 랭킹, 오늘 미션 체크리스트. 레벨바는 넣지 않음. 오른쪽에는 출석·미션/우편함·상점/도감·보관함/게시판·설정 등을 카드 및 탭으로 배치하되 최종 정보 구조는 기능 명세와 사용자 승인에 따름.
- 도감은 스티커·수집 노트의 감성, 작은 실제 스프라이트와 필요한 경우 큰 표정 초상화. 캐릭터 장식/리본/복잡한 배경을 UI 위에 과잉 삽입하지 않는다. 숫자·어휘·버튼이 먼저 읽히도록.
- 책 펼침/페이지 넘김은 명료한 전환과 낮은 비용의 애니메이션 우선. 큰 투명 이미지와 DOM 레이어, 상시 파티클/복잡한 필터를 남발하지 말고 지연과 터치 응답을 검수한다. 실제 성능 측정 전 빠르다고 단정하지 않는다. 기능 UI는 픽셀 감성을 유지하되 한국어 가독성·터치 가능 영역 확보.

## 8. 제작 검수 게이트

1. 참조를 얼굴/색/비례/행동/공간으로 분리하고 권리 확인. 실제 도구 연결, 비용/수량/잔액 확인 및 승인.
2. 신규 캐릭터 정면 스프라이트 소수 비교판과 실제 방 합성. 원본 PNG/캔버스/bbox/정수확대/알파 0·255/외곽선/팔레트/발점 기록. 눈·미간·몸 비례·실루엣을 사용자 선택 전에 임의 확정하지 않는다.
3. 승인된 정면과 동일 캐릭터 ID로 방향 확장 → 이동 → 행동/표정 → 의상. 각 단계에서 픽셀 검사·육안 시각 비교·착용/실제 게임 화면 검수. 실패해도 기존 승인 에셋과 원본 후보 보존.
4. 승인 후에만 별도 작업으로 게임 적용 검토. 코드를 수정/배포하거나 main에 병합하기 전에 명시적 승인.
5. 작업 기록에 원본/후보/채택/구현/배포 상태를 구분하고, 비용·생성 도구·실측·검수 근거를 남긴다.
