# 그못섬 픽셀 에셋 제작 기준서

> 확정: 2026-11-12 · 우선순위: 최신 사용자 지시 > 이전 생성 이미지/과거 규격
>
> **가장 중요한 규칙: 새로 만드는 에셋 한 개의 불투명 픽셀 색은 기본 2색, 최대 3색입니다. 외곽선 색을 반드시 포함하며, 투명 배경은 색상 수에서 제외합니다.**

## 1. 색상 예산 (엄격)
- 기본: **총 2색** = 외곽선 1색 + 내부 면 1색.
- 꼭 필요한 경우: **총 3색** = 외곽선 1색 + 내부 기본색 1색 + 보조색 1색.
- **3색 초과 금지.** 외곽선/하이라이트/그림자/장식/무늬도 색상 수에 모두 포함합니다.
- 투명 픽셀(`alpha=0`)은 제외합니다. 가장자리의 반투명 색을 만들지 않습니다(표준 에셋 알파는 0 또는 255).
- 한 시트에 여러 아이템을 모아 놓더라도 색은 **각 독립 아이템 기준**으로 계산합니다. 게임에 들어갈 파일은 아이템별 독립 PNG로 저장합니다.
- 예시: 갈색 선 + 크림 면(2색), 갈색 선 + 크림 면 + 분홍 포인트(3색). '크림 2색 + 그림자 2색 + 외곽선' 같은 구성은 불합격입니다.
- **기존 승인된 빈방 원본과 8방향 고양이는 원본 보존 대상**입니다. 이 규칙을 적용한다며 원본을 임의 재색칠하거나 재생성하지 않습니다. 새로 제작하는 벽지·바닥·가구·소품에는 동일한 색수 제한을 적용합니다.

## 2. 외곽선 및 도트
- 최신 참고: 사용자가 2026-11-12 제공한 `IMG_6125.jpeg`의 **또렷하고 각진 도트, 짙은 갈색 계열의 연결된 윤곽선**. 디자인·배치를 그대로 베끼는 기준이 아니라 **표현 스타일 기준**입니다.
- 제작 그리드 기준 **1픽셀 외곽선**, 모든 변과 모서리에서 연결되어야 합니다. 윤곽선에 다른 톤을 추가하면 그 톤도 위 3색 제한에 포함됩니다.
- 그라데이션, 흐림/블러, 안티앨리어싱, 부드러운 경계, 부유하는 색 번짐, 납작한 픽셀 위에 부드러운 붓질을 섞는 방식 금지.
- 모든 윤곽·몸체·다리·앞면·장식이 완전히 보이게 넉넉한 투명 여백을 유지합니다. 원본을 자르는 방식으로 사라진 부분을 억지로 복원했다고 표시하지 않습니다.
- 최종 렌더는 `imageSmoothingEnabled=false`, 최근접 이웃 보간만 사용합니다. 이미지 가로·세로를 서로 다른 배율로 늘리지 않습니다. **정수배 확대 권장**. 축소가 필요할 경우 처음부터 실제 게임 픽셀 크기에서 다시 설계하고 검수합니다.

## 3. 고정된 게임 방향 및 에셋 원본
- 기준 게임 화면: **4:3**, 논리 좌표 **170×128**, 정면에 가까운 **미들앵글 2.5D**. 임의의 탑다운/사선 시점으로 가구를 바꾸지 않습니다.
- 테마: 사용자 지정 **핑크 겨울 다락방**. 기본 방은 벽·창문·바닥 등의 건축 요소만 포함합니다. 조명, 화분, 스크린, 선반, 러그, 가구는 별도 배치 에셋입니다.
- **기존 8방향 고양이를 반드시 그대로 사용**: `src/assets/selected-room-20261112/cat/`의 8 PNG와 `src/selected-cat.js`의 방향 전환 로직을 변경하거나 새 고양이로 대체하지 않습니다.
- 기본 가구 배치는 사용자가 제공한 **원본 완성 합성 사진**의 상대 위치와 비율을 기준으로 합니다. 이전에 임의 생성한 예시 배치는 기본 배치로 채택하지 않습니다.
- 새로운 가구는 원본 디자인을 참고하되 시점을 일치시키고, 독립된 투명 PNG·고유 ID·기준 크기·발점(anchor)·배치 면(벽/바닥/러그/상판)을 명시합니다.
- 기존 49/54개 추출본과 2026-11-12에 만든 생성 시트는 **품질 및 색상 기준 통과가 확인되지 않은 참고·재제작 대상**입니다. 개별 검사 없이 실게임에 넣지 않습니다.

## 4. 에셋 1개당 출고 검사
1. 불투명 RGB 색상 수를 스크립트로 세어 **2색을 목표, 3색 이하**임을 확인합니다(투명색 제외).
2. 알파값은 `0/255`만 존재해야 합니다. 픽셀 축소 후 흐림, 번짐, 색수 증가가 없는지 검사합니다.
3. 투명 여백과 잘림, 1픽셀 외곽선 연결, 앞면·다리·장식 누락 여부를 확인합니다.
4. 가로/세로 비율을 유지하고, 실제 콘솔 크기에 미리보기 렌더해 윤곽이 유지되는지 확인합니다.
5. 배경·가구·고양이를 독립 레이어로 합성하며 원본 사진의 기본 위치/크기를 비교합니다.
6. 실게임 통합 시 8방향 고양이, 드래그, 발점 깊이 정렬, 저장 복원, 모바일 가로·세로, 공개 배포를 **각각 별도 검증**합니다.
7. 어떤 기준을 통과하지 못했는지 명시합니다. 생성 시안·검수본·커밋·배포 완료를 동일한 상태로 취급하지 않습니다.

## 5. 규격 충돌 및 버전 관리
- 이전에 언급한 **6색 이하**, 여러 단계 명암, 색이 많은 생성 이미지, 부드러운 픽셀 처리 제안은 **이번 확정 규격에 의해 폐기**합니다.
- 기존 `src/art-style.js`에는 부드러운 리샘플링 코드가 남아 있어 **현재 게임 렌더링 전체가 이 규격을 충족한다고 주장하지 않습니다.** 실제 코드 수정·새 아트 적용은 후속 작업입니다.
- 시점·크기 규칙은 [카메라/배치 기준서](room-camera-standard.md), 작업 중 우선 기억은 [프로젝트 메모리](../MEMORY.md)에 연결합니다.
